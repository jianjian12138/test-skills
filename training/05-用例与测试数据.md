# 第 5 篇：用例与测试数据（第 3–4 阶段）

> 本篇目标：把上一阶段的「测试点」变成**能直接用的用例表格**，并学会**造测试数据、脱敏、管理多套环境配置**。对应技能：`qa-test-case-gen`（第 3 阶段）、`qa-test-data` 与 `qa-env-config`（第 4 阶段）。

---

## 5.1 第 3 阶段：`qa-test-case-gen`（用例生成）

### 痛点

测试点有了，但手工调 Excel 格式、填列名、排层级很费时间，而且每个人格式都不一样，难统一。

### 它做什么

你给它**结构化的用例 JSON**，它用确定性脚本直接生成**统一格式的 Excel（.xlsx）和 Xmind（.xmind）**，列名与层级一致、开箱即用。

### 怎么用

> 「把 `02-analysis/testpoints.md` 里的测试点写成用例，导出 Excel 和 Xmind，放到 `03-cases/`。」

AI 加载 `qa-test-case-gen`，先内部组织成结构化用例 JSON，再调用脚本：

```bash
# 生成 Excel + Xmind（具体参数以技能 SKILL.md 为准）
python .workbuddy/skills/qa-test-case-gen/scripts/gen_case.py \
    --cases 03-cases/cases.json \
    --xlsx 03-cases/cases.xlsx \
    --xmind 03-cases/cases.xmind
```

产物：
- `cases.xlsx`：标准用例表（用例ID、模块、标题、前置、步骤、预期、类型、优先级…）
- `cases.xmind`：思维导图版，适合评审汇报
- `cases.json`：机器可读源，便于追溯与再生成

> 它还带 `expand_cases.py`（边界库自动扩充，如精度/编码/长度边界）和 `trace_matrix.py`（用例↔需求追溯矩阵），保证用例覆盖可追溯。

### 边界用例自动扩充

`expand_cases.py` 能根据字段规格自动补边界值（比如金额字段除了「正常 100」，还会补「0、负数、超大数、小数精度」），减少人工漏想。

## 5.2 第 4 阶段：`qa-test-data`（测试数据）

### 它做什么

为执行/自动化**准备测试数据**：边界值/等价类取值、异常输入、批量造数，以及对敏感字段做 **PII 脱敏**（避免真实个人信息进测试库）。输出 CSV/JSON。

### 怎么用

> 「给『用户注册』造 20 条测试数据，手机号脱敏，输出 `04-testdata/users.csv`。」

或手动跑脚本（示意）：

```bash
python .workbuddy/skills/qa-test-data/scripts/gen_data.py \
    --spec 04-testdata/fields.json \
    --out 04-testdata/users.csv --rows 20
```

### PII 脱敏（很重要）

测试库最怕塞真实身份证/手机号/邮箱。`qa-test-data` 会对标注字段**自动打码**：

| 原始 | 脱敏后 |
|---|---|
| 13812345678 | 138****5678 |
| zhangsan@x.com | z****@x.com |

> 短串全打码、长串首尾保留，既保护隐私又保留可辨识度。

## 5.3 第 4 阶段：`qa-env-config`（多环境配置）

### 痛点

接口/UI 自动化要连不同环境（dev / test / prod），base URL、账号、token、DB 连接各有不同，写在代码里既乱又容易泄露。

### 它做什么

生成各环境的 **`.env` 模板脚手架**，把配置与代码分离，并约定环境切换规范。

### 怎么用

```bash
python .workbuddy/skills/qa-env-config/scripts/init_env.py \
    --outdir 04-testdata/env --envs dev,test,prod
```

会生成：
- `.env.example`（模板，提交到仓库，不含真实值）
- `.env.dev` / `.env.test` / `.env.prod`（各环境配置，真实值本地保管，不入库）

> 原则：**`.env.example` 进版本库，含真实密钥的 `.env.*` 绝不入库**（配合 `.gitignore`）。

## 5.4 一个串联示例

把第 4、5 篇连起来，一轮「用户登录」的数据与用例准备：

```
02-analysis/testpoints.md        （测试点，来自第 4 篇）
        ↓ qa-test-case-gen
03-cases/cases.xlsx             （正式用例表）
03-cases/cases.xmind            （思维导图）
        ↓ qa-test-data
04-testdata/login_data.csv      （20 条登录测试数据，密码脱敏）
        ↓ qa-env-config
04-testdata/env/.env.test       （测试环境 base URL + 测试账号）
```
