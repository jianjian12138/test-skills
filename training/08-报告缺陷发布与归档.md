# 第 8 篇：报告、缺陷、发布与归档（第 7–8 阶段）

> 本篇目标：测试跑完之后做什么？出报告、提缺陷、验缺陷、卡发布、归档。对应技能：`qa-report`、`qa-bug-report`、`qa-bug-verify`、`qa-release-check`（第 7 阶段）和 `qa-archive`（第 8 阶段）。

---

## 8.1 第 7 阶段：`qa-report`（测试报告）

### 它做什么

当测试执行完成——功能用例已在 Excel 填好执行结果，和/或已有 `qa-api-runner` 的 `results.json`——用它生成**汇总测试报告**：

- 自动统计**通过率**
- 各**模块分布**
- **缺陷与阻塞**分布
- 质量评估与**上线建议**

### 怎么用

> 「基于 `03-cases/cases.xlsx` 的执行结果和 `06-execution/results.json`，生成测试报告，写入 `07-report/test-report.md`。」

还支持**多轮趋势对比**（`trend_compare.py`）：把几轮结果放一起，看通过率是向好还是恶化。

> 报告不是装饰。它回答老板最关心的问题：「这版能发吗？」——`qa-report` 会基于数据给明确的质量评估与建议。

---

## 8.2 提缺陷：`qa-bug-report`

### 它做什么

测试发现缺陷时，把**缺陷 JSON 转成标准化 Markdown 缺陷报告**，并生成主流缺陷平台（TAPD / 禅道 / Jira）可直接用的**字段映射载荷**。还带 `rate_severity.py` 给缺陷定级。

### 怎么用

> 「把这个失败用例转成缺陷单，按 Critical/High/Medium/Low 定级，生成可以提 Jira 的字段。」

产物：
- `bug_report.md`：人读版缺陷单（标题、复现步骤、预期/实际、环境、严重级）
- 平台字段映射 JSON：直接贴进 TAPD/Jira 创建接口或表单

---

## 8.3 验缺陷：`qa-bug-verify`

### 它做什么

缺陷（来自 `qa-bug-report`）**修复之后**，规划并执行验证与回归：
- 按原复现步骤重跑
- 逐条核对验收标准
- 根据缺陷影响的模块/代码**推导关联回归范围**（防止「修一处坏一片」）

### 怎么用

> 「缺陷 #123 已转『待验证』，生成验证计划，并推导需要回归的范围。」

产物 `verify_plan.md`：验证步骤 + 回归范围清单。

---

## 8.4 卡发布：`qa-release-check`（上线门禁）

### 它做什么

在生产发布**前后**核验是否具备上线条件，生成三类清单：
1. **上线门禁清单**：构建 / DB 迁移 / 配置 / 依赖 / 回滚方案
2. **上线冒烟（smoke）清单**
3. **发布后监控清单**

### 关键：聚合 signals 做发布阻断

`qa-release-check` 会扫描 `signals/` 目录，**任一 `blocking=true` 即 exit 1 阻断发布**。这意味着第 9 篇讲的那些横切门禁（a11y 违规、flaky 超阈、硬编码密钥…）只要没过，发布就被卡住——这是 fail-closed 落地的关键。

```bash
python .workbuddy/skills/qa-release-check/scripts/gen_release_checklist.py \
    --release release.json --signals-dir signals --out release-checklist.md --fail-on
```

---

## 8.5 第 8 阶段：`qa-archive`（一键归档）

### 它做什么

一轮变更/测试周期结束时，把**全部产物**（需求、用例、执行结果、报告、缺陷）打包成一个**带时间戳与清单 manifest 的归档**，使整个测试生命周期可追溯、可复盘、可还原交付审计。

### 怎么用

```bash
python .workbuddy/skills/qa-archive/scripts/archive_change.py \
    --change changes/user-login-test --out 08-archive/
```

产物：`archive.zip` + `manifest`（记录每项产物来源），审计时一键还原「当时测了什么、结论是什么」。

---

## 8.6 完整收尾链路

```
执行完成
   ├─ qa-report          → test-report.md（通过率/质量评估/上线建议）
   ├─ qa-bug-report      → bug_report.md + 平台字段（发现缺陷时）
   ├─ qa-bug-verify      → verify_plan.md（缺陷修复后）
   ├─ qa-release-check   → release-checklist.md（聚合 signals 卡发布）
   └─ qa-archive         → archive.zip + manifest（归档审计）
```

## 8.7 小结

| 技能 | 阶段 | 关键能力 |
|---|---|---|
| `qa-report` | 07 | 通过率/模块/缺陷分布 + 趋势对比 + 上线建议 |
| `qa-bug-report` | 07 | 缺陷单 + 平台字段映射 + 严重级定级 |
| `qa-bug-verify` | 07 | 验证计划 + 关联回归范围推导 |
| `qa-release-check` | 07 | 上线/冒烟/监控三清单 + 聚合 signals 阻断 |
| `qa-archive` | 08 | 时间戳归档 + manifest，全生命周期可追溯 |
