# 第 2 篇：安装与环境准备（小白第一步）

> 本篇目标：手把手带你把这套测试技能装到你的 AI 助手里，并确认安装成功。即使你没写过代码，跟着做也能完成。

---

## 2.1 先搞清楚：你要装到哪儿？

这套技能是给 **AI 编程助手（Agent）** 用的插件，不是给普通软件装的。常见的「宿主」有：

- **WorkBuddy**（本套件的原生平台）
- **Claude Code / Cursor** 等支持 Agent Skills 标准的工具
- 任意兼容 Anthropic Agent Skills 开放标准的 agent

> 核心认知：**技能 = 一份 `SKILL.md` + 几个 Python 脚本**，放在宿主能扫描到的 `skills/` 目录里。装，本质上就是「把技能文件夹复制过去」。

---

## 2.2 前置条件（自检清单）

| 条件 | 要求 | 说明 |
|---|---|---|
| Python | 3.8+（推荐 3.10+） | 治理/编排层与 Agent 测试层共 36 个技能纯标准库即可；仅执行层 4 个技能需额外 pip 包 |
| Git Bash 或 PowerShell | 任一 | 用来跑安装脚本（Windows 用 PowerShell，mac/Linux 用 Bash） |
| 目标项目目录 | 一个空的或已有的项目根目录 | 技能会装到这个项目下的 `skills/` 子目录 |
| 网络 | 仅执行层 4 技能需联网装 pip 包 | 治理层不需要 |

> 执行层 4 个技能要的 pip 包：`requests`、`openpyxl`、`playwright`（UI 自动化）。如果你只用到治理层/单点技能，可以完全不装这些。

---

## 2.3 仓库结构（心里有数）

你拿到的源码仓库（例如 `test-skills/`）长这样：

```
test-skills/
├── install.sh          ← 安装脚本（Git Bash / macOS / Linux）
├── install.ps1         ← 安装脚本（Windows PowerShell）
├── README.md           ← 项目总览
├── SKILLS_DELIVERY.md  ← 甲方交付手册（功能/门禁/FAQ 全集）
├── LICENSE
├── make_dist.sh        ← 打包分发包用（维护者用，你一般不用）
└── .workbuddy/
    └── skills/         ← ★ 源技能目录（40 个技能都在这里）
        ├── qa-orchestrator/
        ├── qa-api-runner/
        ├── qa-a11y/
        └── ...（共 40 个）
```

> **记住**：源技能目录固定是 `<仓库根>/.workbuddy/skills`。安装脚本就是把这个目录复制到「目标项目」的技能目录。

---

## 2.4 三种安装方式（flavor）

安装脚本支持三种目标（`flavor`），对应不同宿主：

| flavor | 装到哪个目录 | 用于 |
|---|---|---|
| `workbuddy`（默认） | `./.workbuddy/skills` | WorkBuddy 项目 |
| `claude` | `./.claude/skills` | Claude Code / Cursor |
| `generic` | `./skills` | 其他兼容 agent |

### 方式 A：装到 WorkBuddy（最常用）

在**目标项目根目录**打开终端，用路径指向源码仓库的安装脚本：

```bash
# macOS / Linux（Git Bash）
/path/to/test-skills/install.sh

# Windows（PowerShell）
& "D:/path/to/test-skills/install.ps1"
```

默认 `flavor=workbuddy`，会装到当前目录的 `.workbuddy/skills`。

### 方式 B：装到 Claude / Cursor

```bash
/path/to/test-skills/install.sh --flavor claude
```

### 方式 C：装到任意指定目录

```bash
/path/to/test-skills/install.sh --target /你的/项目/路径/skills
```

---

## 2.5 ⚠️ 最常见的坑：源=目标守卫

如果你**直接在源码仓库根目录**运行 `./install.sh`（不加任何参数），会看到这段报错：

```
❌ 源目录与目标目录相同（.../.workbuddy/skills），无法原地复制。
   请显式指定目标： ./install.sh --target /path/to/agent/skills
   或换用其他 flavor： ./install.sh --flavor generic
```

**原因**：默认 `flavor=workbuddy` 的目标就是 `./.workbuddy/skills`，而源也是它自己 → 自己复制自己，当然不行。

**解决办法（三选一）**：
1. **在目标项目目录里调用**（推荐）：`cd 你的项目 && /path/to/test-skills/install.sh`
2. 换 flavor：`/path/to/test-skills/install.sh --flavor generic`（装到 `./skills`）
3. 显式指定目标：`/path/to/test-skills/install.sh --target /别处/skills`

## 2.6 验证安装成功

安装脚本最后会打印类似：

```
✅ 已安装 QA skills 套件到: ./.workbuddy/skills (flavor=workbuddy)
   共 40 个技能目录（含 qa-orchestrator 编排与各阶段技能）
```

确认三步：

1. **看数量**：目录里应有 **40** 个 `qa-*` 文件夹（含 `qa-orchestrator`）。
2. **重新加载宿主**：关闭再打开 WorkBuddy / Claude，让它重新扫描 `skills/` 目录。
3. **试调用**：在对话里说一句「帮我做接口文档」或「检查这次发布能否上线」，看它是否加载了 `qa-api-doc` / `qa-release-check`。

> 如果你只想验证文件到位，也可以直接看目录：
> ```bash
> ls .workbuddy/skills | grep -c qa-    # 应显示 40
> ```

## 2.7 装多少？——三档采用套餐

不要被「40 个」吓到。按你的实际需要选：

- **Starter（最轻）**：只复制你需要的那 1–2 个技能文件夹（比如只要 `qa-api-runner`）。适合解决单点任务。
- **Gates（加门禁）**：在 Starter 基础上，再带上 `signals/` 契约概念和 `qa-release-check`，把质量卡点挂进 CI。
- **Full（全量）**：把 40 个全装上，再启用 `qa-orchestrator` 做全生命周期编排。

> 经验：**先从 Starter 用起来**。遇到「下一步该用谁」的问题，再升级到 Full 用编排器。38 个传统技能（含 `qa-orchestrator`）彼此独立，2 个 Agent 测试技能按需取用，少装几个完全不影响其他技能工作。
