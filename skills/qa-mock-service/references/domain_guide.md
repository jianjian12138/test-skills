# qa-mock-service (下游依赖未就绪时的 Mock 服务) — 领域深度参考指南

## 1. 三类 Mock 选型
| 类型 | 适用场景 | 实现要点 | 风险 |
| :--- | :--- | :--- | :--- |
| **静态响应桩** | 下游接口契约已冻结、只需固定响应 | 按 OpenAPI schema 生成样例 JSON；字段类型与枚举值严格对齐 | 真实下游字段演进后未同步，造成「Mock 全绿、联调全红」 |
| **状态化 Mock** | 需验证多步流程（下单→支付→发货） | 维护调用序号→响应映射，支持按 trace_id 隔离会话状态 | 状态未重置导致用例间污染 |
| **故障注入 Mock** | 需稳定复现超时、500、异常业务码 | 配置错误码/延迟/断连开关，可按需触发 | 忘记关闭注入，误判为真实缺陷 |

## 2. 状态序列设计
- 用 `call_index` 作为状态机游标；每次调用按序返回预置响应序列，序列耗尽后默认返回最后一个响应并标记 `sequence_exhausted=true`。
- 多租户/多会话场景必须按 `trace_id` 或租户 ID 分桶，避免串扰。

## 3. 故障注入矩阵（必测项）
- 网络层：延迟 > SLA、连接重置、部分丢包。
- 协议层：HTTP 500/502/429、非 JSON 响应体、缺失必填字段。
- 业务层：异常业务码、幂等冲突、余额不足、库存超卖。
- 每条注入项需有对应的「上游是否正确降级/重试/提示」断言，否则不算有效 Mock 用例。

## 4. 边界：Mock 不得替代真实联调
- Mock 只解除「下游未就绪」的阻塞，不能作为上线依据；下游就绪后必须跑一轮真实集成回归。
- 禁止把 Mock 指向生产域名；Mock 服务仅绑定 `127.0.0.1`。
- Mock 响应中的用户数据必须是 `qa-test-data` 生成的合成数据，不得回填真实 PII 或生产密钥。

## 5. 关联工具与阶段协同
- **生命周期阶段**：`tdm_cases`
- **推荐协同技能**：`qa-test-data`（合规造数）、`qa-shadow-replay`（HAR 流量回放）、`qa-api-contract`（OpenAPI 契约解析与破坏性变更检测）。
- **CLI 探测**：`python3 qaskills.py route "下游依赖未就绪 Mock 造数"`。
