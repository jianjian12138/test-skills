# 四层代码架构（four-layer-arch）

UI 自动化代码的工程组织，与知识库配合：知识库是「AI 怎么理解页面」，四层架构是「代码怎么组织」。

```
用例层 (test cases)      —— 只写业务步骤，不出现选择器
   ↓ 调用
页面层 (page objects)    —— 每个页面对应一个 PO 类，暴露业务动作
   ↓ 调用
元素层 (element layer)   —— 所有选择器集中在此，改一处全局生效
   ↓ 调用
工具层 (utils)           —— 等待、登录态、报表、公共方法
```

## 职责
- **元素层**：唯一允许写选择器的地方。`getByTestId('btn-add')` 等集中维护。
- **页面层**：`login_page.click_add()` 这类语义动作；页面结构变了只改这里。
- **用例层**：`test_create_config(): 登录→新增→断言列表+1`，纯业务，稳定。
- **工具层**：登录态注入、智能等待、Allure 步骤封装。

## 与知识库映射
知识库的输出直接落到四层：
- 元素描述 → 元素层
- 操作模式 → 页面层（PO 方法）
- 选择器规则 → 命名规范（元素层写法）

没有知识库的四层架构：选择器集中了，但 AI 每次生成还要从零探查页面，效率低。
没有四层架构的知识库：AI 知道选择器，但生成的代码到处散落选择器，维护成本高。
两者结合才是完整基建。
