## 1. 四角色核心结论

### 1.1 测试专家（6.0）
**强项**：`qa-flaky-detect` 用 Wilson 95% 下界判不稳（教科书级）；`qa-a11y` 是真 WCAG 引擎（相对亮度/对比度真算）；`qa-api-contract` 35 规则强 diff；`qa-risk-based`/`qa-exploratory` 真教方法论；全仓"能力边界"诚实声明密集。
**P1 硬伤**：
- `expand_cases.py:90-135` pairwise 算法只让候选相对种子改 1 个参数，**双非种子组合永不可达**（2×2×2 仅 75% 覆盖）→ 用例设计"假最小覆盖"。
- `t_pairwise`（`run_all_tests.py:213-227`）只断言 `len>=4`，**假绿**掩盖上述缺陷。
- `qa-api-runner/engine.py:224` 无 `status` 断言符且 `passed` 强制 `status_code<400`，**无法做 4xx/5xx 负向测试**。

### 1.2 skills 专家（7.0）
**强项**：双 CI 闸真跑 PASS（`validate_portability` 40 技能/72 脚本；`check_drift` 无漂移）；信号契约 SSOT（逐字节一致+机器校验 schema）；渐进披露 40/40 达标；description 含触发词、≤398 字利于发现；依赖分层声明诚实（4 执行层声明 runtime_dependencies）。
**P1 硬伤**：
- `version` 字段 **0/40**（`check_drift.py:47` 关 `--strict-meta`、`validate_portability.py:21` 不强制）→ 无版本则无法版本化升级/跨 agent 包管理解析。
- `REGISTRY.json` 不含 `license`/`runtime_dependencies`/`version` → installer 读后无法 `pip install` 解析依赖。

### 1.3 架构专家（7.5）
**强项**：`stages.json` 单源驱动 route_next/close_loop/check_drift/gen_deps 四路且实证无漂移；`artifact_mismatch` 防黑洞（`route_next.py:83-101`）；`collect_blocking` 仅取 `blocking`（ADR-002 权威正确）；corrupt/stale 信号即阻断；vendoring 落地无 `lib/` 引用；`max_steps` 防死循环。
**P1 硬伤**：
- `grade_run.py:158` `if isinstance(checkers, dict) and checkers:` 真值短路，**空 dict 落 else 不改 success** → P1-7 判分自证漏洞只堵半边（空 list 已修、空 dict 漏）。
- `gen_release_checklist.py:66` 运行时门禁仅查 severity 为 str，**未校验枚举值** → 非法 severity 在 CI 实时路径被放行，事后才由 check_drift 拦。

### 1.4 agent 专家（5.5）
**强项**：双轴定级（ASR+效用保持率）避免过度防御假绿；checkers 为 ground truth 的 R-04 概念正确；fail-closed 默认文化（缺基线/空 checkers→非0）；bootstrap+seed+Wilson 可复现；信号契约"任一 blocking 即阻断、零代码扩展"集成干净。
**P1 硬伤（直接动摇指标可信度）**：
- `gen_task.py:159-161` N 个任务仅同模板克隆 → Pass@k 是单任务重试代数产物（Pass@5=0.999 即 `1-(1-0.75)^5`，与能力上限无关）。
- `calc_metrics.py:275` per_task `pass_hat_k_task(c_i,n_i,k)` 参数反 → n=5,c=4,k=3 输出 **2.5（>1 荒谬）**；聚合值对、明细脏。
- `run_attacks.py:40,62` `multi_turn` 不在 INDIRECT_CHANNELS → 多轮诱导载荷被丢弃，红队 8 面中整面盲区。
- `judge_attack.py:144-169` 拒答短语掩盖真实泄露（output 含凭证但 detect_refusal 命中→判 refused）→ ASR 系统性低估（假绿）。
- `judge_attack.py:240-243` stub 标记用循环末值 `run` 回灌全部 item → 末条 stub 可静默瓦解整批阻断信号。

## 3. 最值得甲方关注的 5 件事

1. **指标可信度被自我高估**：克隆任务(P1-8)、Pass^k 越界(P1-9)、多轮载荷丢弃(P1-10)、拒答掩盖泄露(P1-11) 四者叠加 → 当前发布的 agent Pass@k / ASR 数字**不能直接作为能力/安全背书**。
2. **"全栈 QA"实为"治理门禁 + 部分真检查"**：unit-tdd/mutation/chaos/synthetic 依赖外部工具才成闭环（已诚实声明，但对外叙事需明确"计分"≠"执行"）。
3. **跨 agent 可移植性未闭环**：缺 version、REGISTRY 缺依赖、install 未同包 → 目前以"复制目录/zip"为主，非真正的包管理式分发。
4. **门禁有可绕过接缝**：grade_run 空 dict、severity 枚举未运行时校验、--allow-no-evidence 未互锁 qa_required → fail-closed 哲学在少数接缝未贯彻到底。
5. **自测只验"脚本 I/O"不验"agent 行为"**：对标 skilltest 的"每技能自带 agent 行为测试"，我们是最大结构性差距。
