# 范围与歧义登记（S-xxx）

> 评审过程中出现的歧义/误判，须在依赖项关闭前登记并裁决，避免重复踩坑。

## S-01 ｜ install.sh / SKILLS_DELIVERY.md "缺失" 为路径误判（已裁决）

- **现象**：skills 专家初判 `install.sh`/`install.ps1` "全树无"（P0）、`SKILLS_DELIVERY.md` "缺失"（P2）。
- **核实（实测）**：
  - `D:/test-skills/install.sh` 与 `D:/test-skills/install.ps1` **均存在**（V4 已建）。
  - `D:/test-skills/SKILLS_DELIVERY.md` **存在**（V9 已建于仓库根）。
  - 专家在 `D:/test-skills/.workbuddy/skills/` 内 `find`，而文件在仓库根上一层 → 误判。
- **裁决**：
  - 原 P0"install 完全缺失"**撤销**，降级为 **R-13（P2）**：install 脚本在仓库根、未与 skills 包同目录分发（README 引 `./install.sh` 在包内缺失）。
  - 原 P2"SKILLS_DELIVERY.md 缺失"**撤销**，降级为 **R-30（P3）**：README 相对链接深度错误（`../SKILLS_DELIVERY.md` 应 `../../SKILLS_DELIVERY.md`）。
- **owner**：打包负责人。

## S-02 ｜ qa-code-review 实为真实静态扫描，非"仅规格治理"

- **现象**：项目 memory 旧述"qa-chaos/qa-code-review/qa-synthetic-monitoring 仅校验规格治理"，将三者并列。
- **核实（实测）**：`qa-code-review/scripts/review_scan.py:24-51` 用正则扫 hardcoded secret / SQL concat / 超长函数，是**轻量真实静态检查**（脚本自身 `:5` 声明"非完整 SAST"）。
- **裁决**：以代码为准——`qa-code-review` 是真实（启发式）扫描；仅 `qa-chaos`/`qa-synthetic-monitoring` 为纯规格治理门禁。memory 旧述需修订（见 07 / 后续）。
- **owner**：架构/文档。

## S-03 ｜ "version 字段 0/40" 为真实（非误判）

- **现象**：skills 专家称 40 技能均缺 `version:`。
- **核实**：`grep -rl "^version:" D:/test-skills/.workbuddy/skills/qa-*/SKILL.md` → **0/40**，与声称一致。
- **裁决**：成立为 **R-04（P1）**。validate_portability 的 REQUIRED 不含 version、check_drift `--strict-meta` 默认关，是根因。
