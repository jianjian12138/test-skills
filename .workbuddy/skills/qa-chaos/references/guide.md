# 混沌工程治理门禁指南 — qa-chaos

## 1. 目的
审核「混沌实验规格」是否**受治理**：未受治理的关键实验直接在生产注入故障是无差别破坏，必须阻断。

## 2. 阻断规则
- 规格中存在「关键实验但未定义治理要素」→ 写 `signals/qa-chaos.json` 的 `ungoverned_experiment`，`severity=critical`、`blocking=true`。
- 受治理（定义爆炸半径/回滚/稳态指标）的关键实验 → 放行。

## 3. CLI 约定
```bash
python qa-chaos/scripts/chaos_gate.py --spec chaos/experiment.json --out signals --fail-on
```

## 4. 受治理要素（规格须包含）
- **爆炸半径**：影响范围（单实例/单可用区/全量）与隔离手段。
- **回滚/停止条件**：自动终止阈值（错误率/延迟超界即停）。
- **稳态指标**：判定系统「还活着」的可观测指标（SLO/健康检查）。

## 5. 常见坑
- 「实验清单」≠「治理方案」：只列故障类型不写回滚即判未治理。
- 非关键实验（如本地预发演练）即使未完全治理，通常不触发 critical，但应在规格注明环境。
- 本技能**不执行**实验，仅做规格门禁；真实注入由外部混沌平台完成。
