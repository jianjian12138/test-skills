# 性能指标解读指南（qa-perf-analysis）

## 核心指标

| 指标 | 含义 | 关注点 |
| --- | --- | --- |
| RPS / TPS | 每秒请求/事务数 | 吞吐能力，越大越好 |
| 响应时间 P50 | 中位延迟 | 大多数用户体验 |
| 响应时间 P95 | 95 分位延迟 | 慢请求体验，SLA 常用 |
| 响应时间 P99 | 99 分位延迟 | 长尾，稳定性信号 |
| 错误率 | 失败请求占比 | 稳定性、可用性 |
| 并发用户 | 同时在线虚拟用户 | 负载强度 |

## 分位数怎么读

- **P50 低、P95 高**：大部分快，但有慢请求（偶发慢依赖 / GC）。
- **P95 ≈ P99**：分布均匀，没有长尾。
- **P99 远大于 P95**：长尾严重（锁、慢 SQL、外部超时）。

## 拐点（knee）识别

在 history 里看 RPS vs 用户数：
- 用户数增加 → RPS 线性增加：未饱和。
- 用户数增加 → RPS 不再增加甚至下降：到达拐点（容量上限）。
- 同时错误率上升：已过饱和，系统开始拒绝/失败。

## 资源协同判断

单看 Locust 不够，要对照被压系统的：
- **CPU**：持续 >85% → 计算瓶颈。
- **内存**：持续增长不回落 → 泄漏。
- **DB 连接 / 线程池**：打满 → 后端资源瓶颈。
- **网络 IO / 带宽**：打满 → 网络瓶颈。

## SLA 设定参考

- 内部接口：P95 ≤ 200ms，错误率 ≤ 0.1%。
- 外部交易：P95 ≤ 500ms，错误率 ≤ 1%。
- 大促峰值：按业务容量目标倒推。
