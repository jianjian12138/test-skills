# 性能结果分析检查清单与常见坑（qa-perf-analysis）

## 1. 分析必看项
- [ ] 总吞吐 RPS / TPS
- [ ] 分位延迟 P50 / P95 / P99（非平均）
- [ ] 错误率与错误类型分布
- [ ] 拐点（RPS 不再随并发增长的点）
- [ ] 资源维度关联（CPU/内存/连接是否先到顶）

## 2. 拐点检测
- 用 history 时间序列找 RPS 峰值 = 拐点；拐点后增加并发只增延迟不增吞吐。
- 详情见 analyze_locust.py 的拐点识别输出。

## 3. 资源关联建议
- RT 涨 + CPU 满 → 计算瓶颈
- RT 涨 + 连接等待 → DB/连接池瓶颈
- RT 随时间单调涨 → 内存泄漏 / 缓存退化

## 4. 常见坑
- 用平均值掩盖长尾（P99 才是用户体验）。
- 只看接口不看资源 → 治标不治本。
- 不比对多轮 → 无法判断是否回归。
