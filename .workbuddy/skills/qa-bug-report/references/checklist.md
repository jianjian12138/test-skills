# 缺陷提交检查清单与常见坑（qa-bug-report）

## 1. 缺陷必填项
- [ ] 标题（一句话可定位）
- [ ] 环境（测试/预发/生产 + 版本号）
- [ ] 复现步骤（可逐步重做）
- [ ] 期望结果 vs 实际结果
- [ ] 严重级 / 优先级
- [ ] 附件（截图 / 日志 / 请求响应 / 录屏）
- [ ] 指派人 / 模块

## 2. 严重级判定矩阵
| 影响 | 阻断 | 严重 | 一般 | 提示 |
| --- | --- | --- | --- | --- |
| 核心功能不可用 / 数据丢失 | 致命(S1) | - | - | - |
| 主要功能异常无 workaround | - | 严重(S2) | - | - |
| 次要功能 / 有 workaround | - | - | 一般(S3) | - |
| UI / 文案类 | - | - | - | 提示(S4) |

## 3. 复现步骤模板
```
1. 前置：登录账号 A，进入 X 页
2. 操作：点击 Y，输入 Z
3. 观察：页面报错 E
4. 期望：正常完成，跳转 W
```

## 4. 附件 / 日志采集清单
- 前端：Console 报错 / 网络请求 / 截图
- 后端：traceId / 日志片段 / 入参出参
- 移动：机型 / 系统版本 / 崩溃栈

## 5. 常见坑
- 步骤缺前置 → 开发无法复现。
- 严重级乱评 → 资源错配。
- 只写"有问题" → 必须期望 vs 实际。
- 不贴日志 → 排查慢。
