# 测试点设计模式（testpoint-patterns）

每个可测项至少衍生出 正向 / 负向 / 边界 三类测试点；涉及专项时补充专项视角。

## A. 正向（Happy Path）
- 标准输入、标准流程、预期成功。
- 覆盖主要业务链路与默认配置。

## B. 负向（异常 / 非法）
- 非法输入：错误格式、越界类型、注入字符、超长。
- 越权：无权限角色访问、篡改他人数据、绕过前端校验直连接口。
- 异常流程：网络中断、服务超时、依赖失败、重复提交。
- 错误提示：文案准确、友好、不泄露敏感信息。

## C. 边界（等价类 + 边界值）
- 数值：最小值、最小值-1、最大值、最大值+1、0、负数。
- 长度：空、1 字符、上限、上限+1。
- 集合：0 项、1 项、满额、超额。
- 时间：跨日、跨月、过期、未来时间。

## D. 专项视角
- **性能**：大数据量列表、高频操作、并发提交。
- **安全**：鉴权缺失、越权、敏感信息明文、XSS/SQL 注入点。
- **兼容**：主浏览器、移动端、分辨率。

## 测试点记录格式（一行一条）
```
[模块] <模块名> | [类型] 正/负/边界/专项 | [风险] 高/中/低 | [优先级] P0-P3 | <测试点描述>
```

## 优先级建议
- P0：核心主链路 + 高风险负向。
- P1：重要边界 + 中风险负向。
- P2：次要功能正向 + 低风险的边界。
- P3：边缘兼容 / 探索性。
