# 需求分析检查清单与常见坑（qa-test-analysis）

## 1. 风险矩阵（概率 × 影响）
| | 影响高 | 影响中 | 影响低 |
| --- | --- | --- | --- |
| 概率高 | 必测·优先 | 必测 | 建议 |
| 概率中 | 必测 | 建议 | 可选 |
| 概率低 | 建议 | 可选 | 可选 |

## 2. 常见模块测试点模板库
- **登录**：正常登录 / 错误密码锁定 / 多端互踢 / token 过期 / 第三方登录回跳 / 弱密码策略
- **支付**：重复支付 / 部分退款 / 超时关单 / 金额精度 / 渠道回调伪造 / 并发下单
- **上传**：超大文件 / 非允许类型 / 断点续传 / 病毒文件 / 同名覆盖 / 进度取消

## 3. 歧义澄清话术库
- "支持批量" → 批量上限多少？失败部分如何回滚？
- "快速响应" → P95 具体多少 ms？
- "常用浏览器" → 明确版本清单，避免模糊。
- "安全" → 要防哪类（注入 / 越权 / 爬虫）？有无合规要求？

## 4. 测试点分类
- 正向（happy path）
- 反向（异常输入 / 错误码）
- 边界（极值 / 临界）
- 专项（性能 / 安全 / 兼容）

## 5. 常见坑
- 只列正向 → 异常分支全漏。
- 风险凭感觉 → 用概率×影响矩阵定优先级。
- 测试点不可执行 → 每条必须能写出具体步骤。
- 歧义不追问 → 上线后扯皮。
