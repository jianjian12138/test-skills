# 性能场景设计检查清单与常见坑（qa-perf-design）

## 1. 容量规划公式
- 目标并发 ≈ 峰值QPS × 平均响应时间(秒)
- 所需吞吐 = 业务量 / 时间窗（如日订单 / 峰值小时）
- 拐点识别：逐步加压，RPS 不再随并发增长即为饱和点

## 2. 场景设计检查清单
- [ ] 负载：验证峰值容量达标（SLA）
- [ ] 压力：找拐点 / 极限失败模式
- [ ] 疲劳：中高负载长时，查内存泄漏
- [ ] 尖峰：0→峰值→回落，验恢复
- [ ] 思考时间 / 爬坡 / 时长合理
- [ ] SLA 阈值明确（P95 / 错误率 / TPS）

## 3. 资源监控指标（关联瓶颈）
| 维度 | 指标 | 饱和信号 |
| --- | --- | --- |
| CPU | 使用率 | 持续 >85% |
| 内存 | 堆 / RSS | 只增不减（泄漏） |
| 连接 | DB/Redis 连接数 | 打满 / 等待 |
| 磁盘 IO | await / util | 高延迟 |
| 网络 | 带宽 / 重传 | 丢包 |

## 4. 常见坑
- 并发拍脑袋 → 用公式给起点。
- 只看平均 RT → 必须看分位（P95/P99）。
- 不监控资源 → 找到"慢"但不知"为什么"。
- 单场景跑完就收 → 缺疲劳/尖峰，线上才暴雷。
