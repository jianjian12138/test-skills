# 需求结构化检查清单与常见坑（qa-req-spec）

## 1. 需求完整性检查清单
- [ ] 背景与目标明确（为什么做、给谁用）
- [ ] 范围边界清晰（做什么 / 不做什么）
- [ ] 功能模块列表完整
- [ ] 交互流程（正常 / 异常分支）描述清楚
- [ ] 约束条件（性能 / 安全 / 合规）列出
- [ ] 非功能需求（NFR）可量化（响应时间 / 并发 / 可用性）
- [ ] 验收标准（AC）每条可测、有预期结果
- [ ] 未决问题（open questions）单列并指派跟进人

## 2. NFR 提取模板
| NFR 类型 | 提取问句 | 示例量化 |
| --- | --- | --- |
| 性能 | 峰值 QPS / P95？ | P95 ≤ 500ms，峰值 1000 QPS |
| 安全 | 鉴权 / 加密 / 审计？ | 全链路 HTTPS，敏感字段加密存储 |
| 兼容 | 支持哪些端 / 版本？ | Chrome/Edge 最新 2 版 + iOS 17 |
| 可用 | SLA / 容错？ | 99.9% 可用，降级方案 |
| 数据 | 量级 / 留存？ | 单表 ≤ 1 亿行，留存 180 天 |

## 3. 验收标准（AC）模板
```
场景：<前置条件>
当：<操作>
则：<可观测结果 + 量化阈值>
```

## 4. 需求可追溯矩阵
需求 ID → 测试点 → 用例 ID → 执行结果，逐列对齐，保证"每条需求都被测到"。
可用 `scripts/gen_trace_matrix.py` 由需求列表生成矩阵骨架。

## 5. 常见坑
- 把"用户体验好"当验收标准（不可测）→ 改写为可量化指标。
- NFR 缺阈值 → 压测无判定依据。
- 异常分支只在脑子里 → 必须落文档，否则用例漏。
- 需求与用例脱节 → 用追溯矩阵兜底。
