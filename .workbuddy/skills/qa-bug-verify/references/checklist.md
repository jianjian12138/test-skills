# 缺陷验证检查清单与常见坑（qa-bug-verify）

## 1. 验证判定标准
- [ ] 原复现步骤可正常通过（期望结果达成）
- [ ] 无副作用（未引入新缺陷）
- [ ] 相关边界 / 异常分支同步验证
- [ ] 日志 / 监控无异常

## 2. 回归范围推导规则
- 直接关联：缺陷所在模块 / 接口 / 页面
- 上下游：调用方 / 被调用方 / 共享数据
- 公共组件：改动基础设施 → 扩大回归
- 历史易错：该模块过往高频缺陷

## 3. 回归用例挑选
- 优先：冒烟集 + 缺陷相关用例 + 边界用例
- 按需：全量回归（核心变更 / 发布前）
- 自动化：接口回归优先自动化，UI 回归抽样

## 4. 通过 / 不通过判定
- 通过：原缺陷消失 + 无新缺陷 + 回归集绿
- 不通过：仍复现 / 引入新问题 → 重新打开（reopen）

## 5. 常见坑
- 只验修复点不验回归 → 修一漏一。
- 不验边界 → 同类问题仍在。
- 凭感觉挑回归范围 → 用推导规则兜底。
