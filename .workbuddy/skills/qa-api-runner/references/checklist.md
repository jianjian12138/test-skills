# 接口自动化检查清单与常见坑（qa-api-runner）

## 1. 断言类型检查清单
- [ ] 状态码（2xx/4xx/5xx）
- [ ] 业务码 / message
- [ ] 关键字段存在与类型
- [ ] 数值 / 字符串比较（eq/ne/gt/lt/ge/le/contains/in）
- [ ] 正则匹配（格式：手机号 / 邮箱 / 订单号）
- [ ] 长度校验（len）
- [ ] JSON Schema 结构校验（schema）
- [ ] 数据库落库断言（run_db_asserts）

## 2. 重试 / 超时 / 变量提取
- [ ] 网络抖动场景配置重试（指数退避）
- [ ] 单请求超时阈值合理（避免挂死）
- [ ] 上下游串联用 `${var}` 提取并传递
- [ ] 提取增强：正则提取 / JSONPath 提取 / 多值取首个

## 3. Allure 字段增强
- [ ] 用例标题 / 严重级 / 标签（@feature/@story）
- [ ] 步骤（step）粒度合适
- [ ] 附件（请求/响应）便于排错

## 4. 常见坑
- 只断言 200 → 业务失败漏测（必须断言业务码）。
- 硬编码 token → 用变量提取，避免过期。
- 串联靠全局变量 → 多用例并发串味，注意作用域。
- 不校验 DB → 接口返回成功但落库错，漏测。
