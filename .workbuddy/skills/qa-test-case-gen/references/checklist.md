# 用例设计检查清单与常见坑（qa-test-case-gen）

## 1. 用例评审清单
- [ ] 每条用例有唯一 ID、前置、步骤、预期
- [ ] 覆盖正向 / 反向 / 边界 / 专项
- [ ] 步骤可执行、预期可观测可判定
- [ ] 无歧义用词（"正常""合理"→ 量化）
- [ ] 数据准备明确（账号 / 环境 / 前置数据）
- [ ] 与需求追溯矩阵对齐（无遗漏需求）
- [ ] 冒烟用例集合已标注（用于准入）

## 2. 用例自动扩充方向（见 scripts/expand_cases.py）
- **边界值**：基于字段类型自动补 min/max/+1/-1。
- **异常值**：空 / null / 超长 / 非法字符 / SQL 片段。
- **组合**：多字段异常的正交 / 两两组合，降冗余。
- **去重**：相同步骤+预期归并，避免冗余维护。

## 3. 常见坑
- 用例颗粒度不一（有的太粗有的太细）→ 统一"一个用例验一个点"。
- 预期含"系统正常" → 必须可观测。
- 只抄需求不设计 → 漏异常。
- 无冒烟集 → 每次回归全量跑，浪费。
