# 测试策略输入 Schema（qa-test-strategy）

```json
{
  "project": "订单中台",
  "version": "v2.0",
  "scope": "下单/支付/退款",
  "objectives": ["核心链路零P0缺陷", "性能 SLA 达标"],
  "types": ["ui", "api", "perf", "security"],
  "schedule": "2 周",
  "entry": ["需求冻结", "测试环境就绪", "提测版本稳定"],
  "exit": ["用例执行率 100%", "无 P0/P1 遗留", "安全高危清零"],
  "risks": ["支付依赖第三方不稳定", "大促流量未知"]
}
```

## 各类型测试策略要点

| 类型 | 策略要点 |
| --- | --- |
| UI | 关键路径自动化 + 兼容性矩阵（浏览器/分辨率） |
| API | 单接口 + 多接口串联 + 异常/边界 + 数据双校验 |
| 性能 | 负载/压力/疲劳/尖峰，定 SLA 再看拐点 |
| 安全 | OWASP 核查 + DAST/SAST/依赖/密钥扫描 |

## 准入（Entry）/ 准出（Exit）准则

- **准入**：需求冻结、环境就绪、提测版本稳定、用例评审通过。
- **准出**：执行率 100%、无高优先级遗留、性能/安全门禁通过、产品签字。
