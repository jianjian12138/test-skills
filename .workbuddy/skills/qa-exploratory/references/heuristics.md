# 探索性测试启发式库（HTSM / Tour / 章程 / 信号）

## 1. HTSM（启发式测试策略模型，James Bach）

| 维度 | 含义 | 自问 |
| --- | --- | --- |
| H — Heuristics | 测试技术/模式 | 用等价类？边界值？状态机？ |
| T — Targets | 待测目标 | 功能/数据/平台/时间/接口？ |
| S — Structure | 系统结构 | 架构？模块？依赖？ |
| M — Models | 参考模型 | 用户模型？业务流？竞品？ |

## 2. 常用 Tour（把「测哪里」变成具体路径）

| Tour | 中文 | 做法 |
| --- | --- | --- |
| Museum Tour | 博物馆 | 逐页/逐接口走一遍，看呈现与文案 |
| Guide Tour | 向导 | 按「官方推荐主流程」走核心路径 |
| Supermodel Tour | 超级模型 | 走最复杂/最长/最华丽的功能链 |
| Money Tour | 卖点 | 走最能「赚钱/转化」的关键路径（下单/支付） |
| Destroy Tour | 破坏 | 非法输入、断网、并发、超大数据 |
| Lazy Tour | 懒汉 | 什么都不填、一路默认、跳过校验 |
| Extreme Tour | 极限 | 边界值、最大长度、最小/空、超量 |
| Antisocial Tour | 反社会 | 多用户抢同一资源、越权、并发修改 |
| Awake Tour | 一觉醒来 | 长时间静置后状态是否丢失（token 过期/会话） |
| Sample Tour | 抽样 | 用典型数据抽样，快速冒烟 |

## 3. 章程（Charter）写法

> 一句话：测什么（区域）+ 用什么策略（方法）+ 找什么（风险）+ 何时停（停止条件）。

```
# C-01 订单导出
目标：验证大数据量订单导出的稳定性与权限隔离
区域：订单列表页 / 导出接口 / 权限中心
方法：Extreme Tour（10w 条）+ Destroy Tour（越权访问他人订单）
风险：大数据量超时、权限越界
停止：覆盖 3 个风险场景 或 时间盒 90min 到
时间盒：90 min
```

## 4. 缺陷苗头信号（边测边记）

- 转圈超过 2s 无反馈 / 无 loading。
- 同一操作两次结果不一致（状态抖动）。
- 报错信息暴露堆栈 / SQL / 路径。
- 刷新后数据丢失 / 重复提交成功两次。
- 移动端键盘遮挡输入框 / 按钮点不到。
- 弱网下出现脏数据 / 幽灵订单。

```

```
